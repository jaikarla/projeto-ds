# 🤝 Guia de Contribuição

Obrigada pelo interesse em contribuir com este projeto.

Este sistema foi desenvolvido como um projeto acadêmico e tem como objetivo apoiar o aprendizado e a aplicação prática de conceitos de engenharia de software e trabalho colaborativo.

## 📋 Código de Conduta

Ao participar deste projeto, todos os colaboradores concordam em:

- Manter uma comunicação respeitosa e profissional;
- Respeitar opiniões, ideias e sugestões dos demais participantes;
- Evitar linguagem ofensiva, discriminatória ou inadequada;
- Colaborar de forma construtiva durante discussões técnicas e revisões de código;
- Zelar pela qualidade e pela integridade do projeto.

Contribuições que desrespeitem essas diretrizes poderão ser rejeitadas.

---

## ❔Como Contribuir

Antes de iniciar uma contribuição:

1. Entenda sobre o projeto em [canvas-visao](./docs/canvas-visao.md);
2. Verifique as Issues existentes para evitar trabalho duplicado;
3. Discuta alterações significativas com a equipe responsável;
4. Crie uma branch específica para sua contribuição.

Exemplo:

```bash
git checkout -b feature/nova-funcionalidade
```

---

## 💻 Padrões de Desenvolvimento

Ao desenvolver novas funcionalidades ou correções:

- Utilize nomes claros e descritivos para arquivos, variáveis e funções;
- Mantenha a organização definida pela arquitetura do projeto;
- Siga os padrões de codificação adotados pela equipe;
- Atualize a documentação quando necessário;
- Adicione ou atualize testes sempre que aplicável.

---

## 🔀 Processo de Pull Request

Para enviar uma contribuição:

1. Certifique-se de que sua branch está atualizada;
2. Realize commits com mensagens claras e objetivas;
3. Envie as alterações para o repositório remoto;
4. Abra um Pull Request e preencha todas as informações pertinentes de acordo com o template disponível.

### Exemplo de título

```text
feat: adicionar cadastro de procedimentos
```

---

## ✅ Revisão de Código

Toda contribuição poderá passar por revisão antes da aprovação.

Durante a revisão, poderão ser solicitados:

- Ajustes de código;
- Melhorias de documentação;
- Correções de testes;
- Adequações aos padrões do projeto.

---

## 📚 Documentação

Sempre que uma alteração modificar o comportamento do sistema, a documentação correspondente deve ser atualizada.

Isso inclui, quando aplicável:

- Diagramas;
- Requisitos;
- Guias de instalação;
- Documentação da API;
- Arquivos de apoio presentes na pasta `docs/`.

---

## 🌱 Boas Práticas

Recomenda-se que todos os colaboradores:

- Façam commits pequenos e frequentes;
- Utilizem mensagens de commit padronizadas;
- Mantenham suas branches atualizadas;
- Testem suas alterações antes de abrir um Pull Request;
- Registrem decisões importantes na documentação do projeto.

---

## 🎓 Natureza Acadêmica

Este projeto possui finalidade educacional e acadêmica.

As contribuições devem priorizar:

- Clareza do código;
- Boas práticas de desenvolvimento;
- Documentação adequada;
- Facilidade de manutenção;
- Compartilhamento de conhecimento entre os integrantes da equipe.

Agradecemos sua colaboração e participação no projeto!
